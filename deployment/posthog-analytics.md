# PostHog optional analytics — review candidate

Project 772000, The Sound Question, America/Halifax. IP anonymization enabled; replay, autocapture, console and performance capture disabled. This static-site integration uses the documented public single-event capture endpoint instead of loading a third-party SDK, to minimize dependencies and payloads. See https://posthog.com/docs/api/capture#single-event. No production credentials are in Git.

## Release gates
- No Cloudflare deployment or main merge without separate explicit owner approval. No paid features.
- Build configuration is off by default. At approved release time, configure the public ingestion token via TSQ_POSTHOG_PROJECT_TOKEN and exact US ingestion host via TSQ_POSTHOG_HOST. These are build environment variables; use the public project token, never a personal API key. Do not publish them in source. The generated HTML necessarily contains the public ingestion token, which cannot read project data.
- Only the production origin sends events. Explicit Allow analytics required; decline or GPC/DNT blocks. Preference stored locally, short-lived random session identifier stored per tab. No full URL query/fragment, raw form input, raw referrer, person profile, replay or automatic clicks.
- Phase 1 sends one pageview per eligible page load, with a coarse source bucket. Session and visitor counts may not match SDK-derived web analytics. Treat as consented pageviews, not total traffic. No engagement/finish events yet.
- Run node --test tests/posthog-analytics.test.mjs; build with no configuration and with a dummy token on a local/GitHub runner. Check desktop/mobile privacy controls and network activity, including blocked/denied states. Check browser CORS and successful real event receipt only on an authorized test/release path. Verify event payload and no extra collection. Confirm free usage/billing safeguards and review retention/data handling before activation.
- Once first real events are verified, add explicitly allowlisted tool-completion events at actual success handlers (not button guesses). Update privacy notice and tests, without transmitting model names, free-form inputs, scores or personal information unless separately reviewed.
